# AssetTrail 안정화 작업

기준일: 2026-07-30
기준 브랜치: `main` (`fd22bad`)
작업 브랜치: `stabilization/assettrail-hardening`

이 문서는 AssetTrail의 정확성, 데이터 내구성, 배포 안전성, 사용성을 순서대로
개선하기 위한 실행 목록이다. 각 단계는 관련 테스트를 통과한 뒤 다음 단계로
넘어간다.

## 1단계 — 운영 기준선 확정

- [x] `main`과 `dev`의 커밋·파일 차이 확인
- [x] PR #6의 병합·배포 전제 확인
- [x] Cloud Run 공개 상태 경로와 인증 경계 확인
- [x] Firestore Rules 소스와 운영 배포 상태의 차이 위험 확인
- [x] GitHub 브랜치 보호·필수 체크 상태 확인

결론:

- 운영 앱의 기준선은 `main`으로 유지한다.
- PR #6은 최신 백엔드 재배포, 실제 로그인 E2E, Firestore/Storage 보안 검증 전까지
  별도 초안으로 보존한다.
- 운영 Cloud Run은 이전 API 리비전이지만 현재 `main` 앱에서는 연결하지 않는다.
- 운영 Firestore Rules 원문은 현재 로컬 인증 환경에서 조회할 수 없으므로,
  제한된 Rules 소스를 저장소 기준으로 만들고 CI에서 검증한다.
- `main` 브랜치 보호와 required check가 없으므로 CI 보강 후 저장소 설정을 적용한다.

- [x] 강화한 Rules를 운영 Firebase 프로젝트에 배포하고 실제 규칙을 확인한다.

운영 Rules는 2026-08-19 12:07:59 KST에 `assettrail-6f676`에 배포했고, 활성 원문과
저장소 파일의 UTF-8 바이트·SHA-256 일치 및 history chunk 경로를 재확인했다. 현재
GitHub API에서는 `main` 보호 설정을 확인할 수 없어 required check 항목은 미완료로
유지한다. 비신뢰 가격 요청은 앱·생성기 양쪽에서 제거했고, PR과 `main` 배포 모두
같은 `test` 게이트를 통과하도록 워크플로를 구성했다.
