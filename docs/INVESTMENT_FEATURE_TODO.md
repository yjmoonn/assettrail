# AssetTrail 투자 기능 TODO

기준일: 2026-08-05
현재 상태: 1~3단계 완료, 4~5단계 대기

이 문서는 AssetTrail을 자산 기록 도구에서 투자 의사결정 운영체계로 확장하기 위한
활성 작업 목록이다. 구현 진행 상황은 이 문서의 체크박스와 단계 상태표를 기준으로
관리한다.

## 상태와 우선순위 기준

- `[ ]`: 대기 또는 진행 중인 작업
- `[x]`: 구현과 필수 검증이 모두 끝난 작업
- `기반 1순위`: 다른 분석 기능의 정확성을 좌우하는 데이터 기반
- `빠른 1순위`: 기존 데이터로 먼저 제공할 수 있는 높은 효용의 기능

## 기능 우선순위와 구현 단계 매핑

| 구현 단계 | 상태 | 매핑되는 추천 기능 | 선행조건 |
|---:|---|---|---|
| 1 | 완료 | 투자 의사결정 센터, 기본 집중도 분석 | 없음 |
| 2 | 완료 | 신규자금 배분 도우미, 수동 실질노출·위험 지도 | 1단계 자산 역할·목표 정보 |
| 3 | 완료 | 거래·현금흐름 원장, CASH 자동 정산 | 1단계부터 데이터 모델 사전 설계 |
| 4 | 대기 | 증권사 CSV, TWR·XIRR, 성과 원인 분석 | 3단계 거래 원장 |
| 5 | 대기 | ETF 실질노출 자동화, 기업 데이터, 보안형 AI 보고서 | 1~4단계의 구조화된 데이터 |

거래·현금흐름 원장은 중요도 기준으로 `기반 1순위`지만 데이터 마이그레이션 범위가
크다. 따라서 기존 데이터로 구현 가능한 1~2단계를 먼저 제공하고, 원장 데이터 모델
설계는 1단계부터 병행한다.

기본 집중 위험을 보여준다.

### 데이터와 도메인

- [x] 자산별 역할을 정의한다: `CORE`, `STRUCTURAL_GROWTH`, `CYCLE`, `TACTICAL`,
  `SURVIVAL`.
- [x] 투자 가설, 기대수익 원천, 투자 기간, 확신도를 저장한다.
- [x] 관찰 KPI·촉매와 가설 무효화·감속 조건을 저장한다.
- [x] `nextReviewAt`, 마지막 검토일, 검토 상태를 저장한다.
- [x] 관심종목은 보유 자산과 분리된 watchlist로 관리한다.
- [x] 3단계 거래 원장을 고려해 이벤트 식별자·자산 식별자 경계를 사전 설계한다.

### 화면과 계산

- [x] 자산 상세에서 가설·역할·검토 조건을 작성하고 수정할 수 있게 한다.
- [x] 대시보드의 검토기한 초과 항목을 클릭 가능한 오늘의 할 일로 연결한다.
- [x] 동일 종목을 여러 계좌에서 보유하면 하나의 경제적 포지션으로 합산한다.
- [x] Top 1, Top 5, HHI 집중도와 데이터 품질 경고를 계산한다.
- [x] PR #6의 결정론적 분석 로직을 현재 데이터 모델에 맞춰 선별 재구현한다.

### 완료 기준

- [x] 검토기한이 지난 자산을 대시보드에서 해당 검토 화면까지 이동할 수 있다.
- [x] 여러 계좌의 동일 종목이 집중도 계산에서 중복 또는 누락되지 않는다.
- [x] 관련 단위 테스트, 데이터 호환 테스트와 데스크톱·모바일 UI 검증이 통과한다.

## 2단계 — 행동 지원

목표: 기존 자산의 불필요한 매도보다 신규자금으로 목표 비중과 위험을 조정하도록
지원한다.

### 신규자금 배분

- [x] 일회성·월 정기 신규자금 입력을 지원한다.
- [x] 자산군별 최소·목표·최대 비중 밴드를 저장한다.
- [x] 목표 미달, 최대 비중 초과, 검토 필요 상태를 함께 반영한다.
- [x] 매도 없이 신규자금만 배분하는 기본 제안을 계산한다.
- [x] 배분 전후 예상 비중과 배분 근거를 표시한다.
- [x] 제안은 주문 지시가 아닌 사용자가 검토할 후보임을 명확히 표시한다.

### 실질노출·위험 태그

- [x] 자산에 산업, 국가, 통화, 금리, 듀레이션, 고객, AI 가치사슬 등의 수동 태그를
  지정할 수 있게 한다.
- [x] 직접 보유와 수동 태그 기준의 중복노출을 집계한다.
- [x] 코어·위성·AI 구조적 성장·사이클 자산의 위험 예산을 표시한다.
- [x] 태그가 없거나 오래 검토하지 않은 자산을 데이터 품질 경고로 표시한다.

### 완료 기준

- [x] 신규자금 배분 총액이 입력 금액과 일치하고 목표 최대 비중을 넘지 않는다.
- [x] 배분 불가 또는 제약 충돌 시 임의 계산 대신 이유를 사용자에게 보여준다.
- [x] 외부 데이터 없이도 수동 태그 기반 노출 지도를 사용할 수 있다.
- [x] 계산 테스트와 주요 빈 상태·경계값 UI 검증이 통과한다.

## 3단계 — 거래·현금흐름 원장

목표: 자산 변화와 외부 현금흐름을 분리해 정확한 잔액과 향후 성과 분석의 기반을
만든다.

### 원장 모델

- [x] `BUY`, `SELL`, `DEPOSIT`, `WITHDRAWAL`, `DIVIDEND`, `INTEREST`, `FEE`, `TAX`,
  `SPLIT`, `VALUATION`, `FX` 이벤트를 정의한다.
- [x] 이벤트에 거래일, 결제일, 수량, 가격, 통화, 거래 당시 환율, 비용, 계좌와
  원본 식별자를 보존한다.
- [x] 기존 보유 자산은 매수 이력을 추정하지 않고 명시적인 기초잔액 이벤트로
  마이그레이션한다.
- [x] 이벤트를 `users/{uid}/financeData/primary/ledgers/{ledgerId}/events/{eventId}`
  세대별 하위 컬렉션에 저장해 단일 문서 크기 제한을 피한다.
- [x] 로컬 저장, 클라우드 동기화, 내보내기·가져오기와 충돌 해결 방식을 설계한다.

### 현금 정산과 정합성

- [x] 매수·매도 시 결제 CASH 계좌를 선택하게 한다.
- [x] 매수는 현금을 차감하고 매도는 비용·세금을 반영한 순현금을 증가시킨다.
- [x] 배당·이자·입출금이 자산 총액과 현금흐름 분류에 함께 반영된다.
- [x] 거래 수정·취소는 원본을 조용히 덮어쓰지 않고 감사 가능한 방식으로 처리한다.
- [x] 기초잔액만 있는 오등록 종목·자산은 정정·취소 이벤트를 남겨 안전하게 복구한다.
- [x] UI 등록과 가져오기에서 중복 자산 identity·중복 ID를 반영 전에 차단한다.
- [x] 포지션 수량, 평균단가, 현금 잔액과 이벤트 합계의 정합성을 검사한다.

### 완료 기준

- [x] 매수·매도 후 주식과 현금 변화가 하나의 작업으로 일관되게 저장된다.
- [x] 기존 사용자 데이터 마이그레이션 전 자동 백업과 실패 시 복구가 동작한다.
- [x] 900KB 사용자 문서 방어와 여러 기기 revision 충돌 처리가 유지된다.
- [x] 데이터·클라우드·Firestore Rules 전체 테스트가 통과한다.

현재 일상 화면은 매수·매도, 입출금·배당·이자·수수료·세금과 MANUAL 평가조정을
지원한다. `SPLIT`과 `FX`는 계산 엔진과 가져오기 스키마에는 정의되어 있지만 직접
입력하는 일상 화면은 후속 작업으로 남긴다. 원장 기준일 이전의 `realizedTrades`는
현재 보유를 이중 차감하지 않도록 SELL 이벤트로 소급 재생하지 않는다. 기존 US
기초잔액의 과거 환율도 추정하지 않으므로 해당 구간의 원화 원가·성과는 미확정이다.

## 4단계 — 정확한 성과 측정

목표: 신규 입출금과 투자 결과를 분리하고, 성과가 발생한 원인을 설명한다.

### 증권사 CSV

- [ ] 증권사별 CSV 어댑터를 독립 모듈로 정의한다.
- [ ] 가져오기 전에 거래 수, 기간, 계좌, 예상 변경을 미리 보여준다.
- [ ] 원본 거래 ID와 보조 키를 이용해 중복 가져오기를 차단한다.
- [ ] 일부 행 오류 시 전체 교체 대신 오류 행과 처리 결과를 보고한다.
- [ ] 개인 식별 정보가 로그나 오류 보고서에 남지 않게 한다.

### 성과와 원인 분석

- [ ] TWR과 XIRR을 계산하고 각 지표의 적용 범위를 설명한다.
- [ ] 자산 증감을 신규 입출금, 가격, 환율, 배당·이자, 수수료·세금으로 분해한다.
- [ ] 기간별 벤치마크 대비 성과를 제공한다.
- [ ] 최대 낙폭, 회복 기간과 변동성을 제공한다.
- [ ] 거래 원장 이전의 과거 스냅샷은 `자산 변화`로 표시하고 투자수익률로 소급
  추정하지 않는다.

### 완료 기준

- [ ] 입출금이 있는 검증 포트폴리오에서 TWR·XIRR 기준값과 일치한다.
- [ ] 기여도 합계가 비용과 반올림 허용범위 안에서 총 변화와 일치한다.
- [ ] 동일 CSV를 반복 가져와도 거래가 중복 생성되지 않는다.
- [ ] 계산 단위 테스트, 가져오기 실패 테스트와 기간별 UI 검증이 통과한다.

## 5단계 — 외부 데이터와 AI

목표: 실제 경제적 노출과 기업 상태를 보강하고, 검증 가능한 계산 결과를 AI가
설명하도록 한다.

### 외부 데이터

- [ ] 미국 종목을 안전하게 등록·검토해 가격 대상에 추가하는 운영 흐름을 만든다.
- [ ] ETF 구성종목의 출처, 기준일, 커버리지와 재배포 조건을 확인한다.
- [ ] ETF 구성종목을 표준 종목 식별자로 매핑하고 직접 보유와 중복노출을 계산한다.
- [ ] 국내 기업은 OpenDART, 미국 기업은 SEC Company Facts를 우선 검토한다.
- [ ] 외부 API는 백엔드 캐시·속도 제한·마지막 정상 데이터 유지 경로를 둔다.
- [ ] 컨센서스처럼 공식 무료 데이터로 충족할 수 없는 항목은 별도 제품·비용 결정을
  거친다.

### 보안형 AI 보고서

- [ ] 개인 식별자와 불필요한 원거래를 제거한 최소 분석 payload를 정의한다.
- [ ] 결정론적 계산값, 데이터 품질과 근거를 AI 입력에 함께 제공한다.
- [ ] AI 문장과 계산값을 구분하고 누락 데이터·불확실성을 표시한다.
- [ ] 클라이언트 API 키 없이 인증된 백엔드에서만 모델을 호출한다.
- [ ] PR #6의 보고서·PDF 코드는 최신 인증·보안·데이터 모델 기준으로 재검증한다.
- [ ] 자동 주문 또는 단정적인 매수·매도 지시를 제공하지 않는다.

### 완료 기준

- [ ] ETF 노출 합계, 기준일과 미매핑 비중을 사용자가 확인할 수 있다.
- [ ] 외부 데이터 실패 시 오래된 데이터 표시 또는 기능 제한으로 안전하게 저하된다.
- [ ] 다른 사용자의 분석 데이터와 보고서에 접근할 수 없음을 E2E로 검증한다.
- [ ] AI 없이도 핵심 계산·위험 경고를 이용할 수 있다.
