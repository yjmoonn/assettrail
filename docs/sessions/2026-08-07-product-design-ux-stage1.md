# Product Design UX 1단계

## 목적

승인된 UX 감사안의 첫 배포 단계를 기존 계산식, 저장 스키마, 데이터 계약을 바꾸지 않고
적용한다. 첫 사용자의 다음 행동, 성과 데이터 부족 상태, 클라우드·백업 경계와 모바일
접근성을 우선한다.

## 핵심 결정

- 빈 상태에서는 결과 영역보다 현재 필요한 한 가지 행동을 먼저 보여준다.
- 성과 결과는 정확한 검증 평가점이 2개 이상일 때만 노출하고, 준비 과정은 4단계로
  설명한다.
- 클라우드 인증·동기화 행동은 설정에 모으되, 저장 위치 상태는 헤더에도 계속 표시한다.
- 주 JSON, Butler, ETF, 비영속 원문의 저장·백업 경계를 설정 화면에서 명시한다.
- 기존 디자인 언어와 바닐라 HTML/CSS/JS 구조를 유지하고 새 프레임워크를 도입하지 않는다.

## 변경

- `index.html`: 대시보드·성과·기록 빈 상태, 설정 클라우드·백업 정보 구조와 충돌 문구.
- `app.js`: 첫 사용 CTA, 성과 준비 체크리스트, 기록·원장 빈 상태, 동기화 상태 문구와
  설정 상태 연동.
- `assettrail-tokens.css`, `styles.css`: 의미색 텍스트, 키보드 포커스, 44px 터치 영역,
  설정 카드와 성과 준비 상태의 반응형 스타일.
- 관련 앱 테스트: 빈 상태, 성과 가드, 백업·클라우드 상태 문구 회귀 계약.

## 검증

- `npm test`에서 `check:js`부터 `test:data`까지의 JS 테스트가 통과했다.
- `test:price-requests`는 기본 Python 환경에 `requests`가 없어 전체 실행이 멈췄다.
  임시 `uv` 환경 재시도도 로컬 Anaconda/NumPy·backports 충돌로 완료하지 못했다.
- `npm run test:firestore`는 로컬 Java 런타임 부재로 실행되지 않았다.
- 인앱 브라우저에서 1440px, 1280px, 430px, 390px의 대시보드·설정·기간 성과를 확인했다.
  가로 넘침이 없고 모바일 주요 CTA가 44px이며, 결과 차트는 준비 전 숨김 상태다.
