# 환율 지연 시 잠정 자산 평가와 갱신 복구

## 목적
환율 일봉 누락 때문에 전체 가격 갱신이 중단되던 문제를 고친다. 사용자가 선택한 정책은 동일 공급자의 마지막 유효 완료 종가를 실제 날짜 그대로 사용하고, 최신 확정 평가와 표시용 잠정 평가를 분리하는 것이다. 원격 반영과 기존 GitHub Pages 배포도 승인됐다.

## 핵심 결정
- Yahoo KRW=X 공급자를 유지한다. ECB 기준환율이나 분봉 재구성을 기존 일봉 종가로 대체하지 않는다.
- 주식의 세션 인증과 품질 기준은 유지한다. 환율은 `FINAL_CLOSE`(기대일 일치) 또는 `DELAYED_CLOSE`(기대일 이전 가용 완료 종가)로 구분한다. 실제 날짜를 기대일로 바꾸지 않는다.
- FX 지연 가격표는 `PARTIAL_FINAL_CLOSE`이며 FX 인증일·인증 만료는 null이다. 기대일은 `expectedFxSession`에 별도로 보존한다. 기존 클라이언트가 전체 최신 확정 인증으로 오인하지 않게 한다.
- 지연 환율에는 `date`, `expectedSession`, `retrievedAt`, `source`, `freshnessStatus`를 보존한다. 방법론의 `fxValuationTiming=LATEST_AVAILABLE_COMPLETED_SESSION`으로 주식의 최근 완료 세션 정책과 구분한다.
- 장기 지연은 경고를 강화하되 표시용 평가의 짧은 만료 조건으로 사용하지 않는다. 기본 조회 기간에 가용 값이 없으면 같은 공급자의 전체 일봉 기간을 조회한다. 유효 값 없음·범위 밖 값·미래/진행 중 행은 채택하지 않는다.
- 지연 환율을 쓰는 미국 자산 포함 조회 기록과 성과 평가점은 새로 확정 저장하지 않는다. 기존 기록·원장에 소급 적용하지 않는다. KRX만 보유한 경우에는 정상 주식 인증으로 저장할 수 있다.

## 원인과 조사 근거
- 실패 job [115169301395](https://github.com/yjmoonn/assettrail/actions/runs/38359259277/job/115169301395) 로그에서 FX 날짜 불일치 3회를 확인했다. 기존 종가 선택기는 기대일 이전 행을 반환했지만 인증기는 기대일 정확 일치를 요구했다.
- 10월 13일 07:23–07:34 UTC Yahoo query1/query2 일봉·날짜 범위·Ticker.history 조회에는 10월 12일 일봉이 없었다. 실제 관측이며 실패 당시 원자료를 확보한 것은 아니다. 회귀 fixture는 합성이다.
- 같은 날짜 시간봉 24개·분봉 1,374개가 존재해 휴일로 제외할 근거는 없었다. 정상 10월 9일도 일봉 1,342.989990과 마지막 분봉 1,340.020020이 달라 분봉을 같은 일봉 종가로 대체하지 않았다.
- [연준 휴일표](https://www.federalreserve.gov/aboutthefed/k8.htm)의 Columbus Day는 Yahoo CCY 전면 휴장 증거가 아니다. [영국 은행 휴일표](https://www.gov.uk/bank-holidays)에 해당 날짜 휴일은 없다. Yahoo 전체 연간 휴일표와 일봉 산출 공식은 확보하지 못했으므로 모든 특수 휴일까지 기존 평일 계산이 맞는다고 단정하지 않는다.
- [yfinance repair](https://ranaroussi.github.io/yfinance/advanced/price_repair.html)는 작은 주기로 재구성한 값이며 공급자 수정값과 달라질 수 있어 활성화하지 않는다.
- [ECB](https://www.ecb.europa.eu/stats/policy_and_exchange_rates/euro_reference_exchange_rates/html/index.en.html)의 10월 12일 기준환율은 확보했지만 기존 종가와 의미가 다르므로 사용하지 않는다. 사용자가 선택한 동일 공급자 정책이 최종 결정이다.

## 변경
- `scripts/generate_prices.py`: FX 런던 시간대 정규화, 유효 완료 종가 선택·재조회, 지연 출처 보존, FX를 제외한 부분 인증, 주식 품질 게이트 유지.
- `app.js`, `index.html`, `styles.css`: 잠정 평가 전역 안내·미국 자산 기준일, 장기 지연 경고, 확정 기록/성과 저장 차단, 새 환율 자동 회복, 무효 FX 별도 안내. 앱/CSS 캐시 키 갱신. 데스크톱 화면 전환 시 고정 메뉴가 잠정 안내를 가리지 않도록 스크롤 여백을 추가했다.
- `tests/generate-prices-requests.test.py`, `tests/app-delayed-fx.test.mjs`, `package.json`: 정상·누락·재조회·장중·미래·NaN·시간대·휴일·장기 지연·부분 인증·기존 산출물/원장/기록 보존·회복 회귀.
- 기존 2개 앱 테스트의 정상 환율 fixture가 2099년 미래 날짜를 사용해 새 검증에 걸렸다. 해당 환율 날짜만 실행일로 수정했다. 관련 제품 로직은 변경하지 않았다. AI export 테스트의 앱 캐시 키 기대값도 실제 index.html에 맞췄으며 AI 기능 코드는 변경하지 않았다.
- 아키텍처·핸드오프에 최종 정책을 기록했다.

## 검증
- 원본 코드에 초기 회귀 3개를 적용해 실패를 재현했다. 사용자 정책 확정 뒤에는 지연 행의 표시용 수용과 최신 인증 금지를 함께 검증하도록 테스트를 갱신했다.
- 최종 전체 `npm test`는 Firestore Rules 포함 종료 코드 0. 이후 부분 인증의 FX 행만 바꿔 최신으로 승격하지 못하게 방어를 추가하고 `test:prices`·`test:performance`도 재통과했다. Node 24.19.0 / Python 3.12 임시 venv / Java 21. CI 환경 검증은 PR에서 별도로 수행한다.
- 실제 로컬 생성 종료 코드 0: 최종 생성 2026-10-13 08:06:35 UTC, FX 조회 08:08:03 UTC. KRX 4,306개·US 24/24개·오류 0. 세션 KRX 10월 13일, US 10월 12일. FX 1,342.989990 KRW/USD, 실제 10월 9일 / 기대 10월 12일 / `DELAYED_CLOSE`. FX 최신 인증은 없음.
- Chromium 홈·자산 화면 1440/1280/390/430px: 잠정 안내·평가값·확정 저장 차단, 가로 넘침 없음, 데스크톱 고정 메뉴의 안내 가림 없음, 브라우저 오류 0. 새 FX 도착 합성 응답으로 경고 해소와 저장 준비 정상 회복 확인. 합성 보유자산만 사용하고 외부 요청은 차단했다.
- 생성물·로그·스크린샷은 /tmp에만 두고 커밋하지 않는다. 개인 원장·보유정보·비밀값을 읽거나 변경하지 않는다.

## 릴리스 상태와 다음 작업
- 사용자 승인에 따라 검증 후 별도 작업 PR → CI → main 병합 → 기존 Pages 배포를 진행한다. 원격 dev에는 무관한 기존 PR #6이 있어 건드리지 않고 로컬 dev에서 만든 수정만 별도 리뷰 브랜치로 전달한다.
- 운영 배포 후 실제 prices.json을 다시 읽고 생성 시각·주식 세션·환율 실제일/기대일/지연 상태를 확인한다. 운영 코드로 격리 브라우저 검증을 수행한다.
- 운영 성공은 배포 및 실제 자료 검증 후에만 확정한다. 다음 정상 FX 일봉이 도착하는 실제 시점은 아직 관찰 전이며 자동 회복은 회귀 테스트로 검증한다.

- PR #72 첫 CI는 마지막 화면 검증에서 갱신한 CSS 캐시 키와 제품 테스트의 구버전 기대값이 달라 실패했다. 제품 로직 오류가 아니며 기대값을 새 캐시 키로 맞춘 최종 파일 상태로 전체 npm test(Firestore Rules 포함)가 종료 코드 0으로 통과했다. 수정 커밋의 PR CI도 통과해야 병합한다.
