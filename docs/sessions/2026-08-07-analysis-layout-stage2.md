# 분석 탭 UX 구조 개선

## 목적

분석 탭의 Butler 실적, ETF 실질노출, 보안형 AI 보고서가 서로 다른 높이와 위치에 동시에
노출되며 생기던 배치 불안정과 다음 행동 혼란을 줄인다. 기존 계산식, 로컬 저장 경계,
클라우드 스키마와 외부 데이터·ETF·AI 계약은 그대로 유지한다.

## 핵심 결정

- 분석 진입점에서는 세 작업의 현재 상태와 필요한 다음 행동을 먼저 비교한다.
- 사용자가 선택한 작업 패널 하나만 표시하고 선택 상태는 현재 화면 세션에서 유지한다.
- 주 행동은 패널 헤더에 남기고 백업·복원·초기화 등 저빈도 행동은 펼침 영역에 둔다.
- 보고서 본문은 바로 읽되 내부 FACT/evidence ID는 요청할 때만 공개한다.
- 모바일은 별도 기능 축소 없이 스티키 작업 전환과 단일 상세 영역을 사용한다.

## 변경

- `index.html`: 3개 분석 상태 카드, 선택 패널 구조, 패널별 접힌 데이터 관리 영역.
- `app.js`: 작업 요약 상태 계산, 선택 패널 전환, 키보드 탐색·포커스 안내, 보고서 기술
  근거 점진 공개.
- `styles.css`: 데스크톱 상태 카드, 선택 강조, 데이터 관리 펼침, 720px 이하 스티키 작업
  전환과 전체 폭 모바일 CTA.
- `tests/app-stage5.test.mjs`: 초기 선택, 클릭·키보드 전환, 패널 가시성, 상태 수치,
  데이터 관리 위치와 기술 근거 펼침 회귀 계약.

## 불변 범위

- Butler 원문 처리·정규화와 별도 로컬 저장 계약을 변경하지 않았다.
- ETF 카탈로그 검증·실질노출 계산과 fail-closed 정책을 변경하지 않았다.
- AI 근거·결정론 보고서 생성과 ChatGPT 수동 전달·검증 계약을 변경하지 않았다.
- 클라우드 스키마, 주 JSON, 데이터 마이그레이션과 투자 계산 공식은 변경하지 않았다.

## 검증

- `npm run check:js` 통과.
- `npm run test:stage5` 통과.
- `npm run test:prices` 통과.
- 인앱 브라우저에서 1440px, 1280px, 430px, 390px 확인.
- 네 화면 폭 모두 문서 가로 넘침 0px, 선택 패널 하나만 노출됨을 확인.
- 모바일에서 작업 전환부 스티키 유지, 기업 실적·ETF·AI 클릭 전환과 제목 포커스를 확인.
- 화살표로 다음 작업에 포커스를 이동하고 Enter로 해당 작업을 선택하는 흐름을 확인.
- 브라우저 콘솔 경고·오류 없음.
