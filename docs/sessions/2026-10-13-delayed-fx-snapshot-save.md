# 지연 환율 조회기록 저장 복구

## 목적
PR72가 허용한 Yahoo 마지막 유효 확정 환율 종가를 조회기록에도 저장한다.

## 핵심 결정
- 유효한 지연 환율만 저장 허용한다. 주식 인증·만료, 잘못된 환율, 저장 실패 및 사용자 전환 방어는 유지한다.
- 환율 실제일·출처·조회시각·기대일·지연 여부·잠정 상태를 당시 값으로 보존한다. 새 환율이 과거 기록을 갱신하지 않는다.
- 주 상태 v10으로 구버전 앱의 손실성 쓰기를 차단한다. 기존 기록은 백업·검증 후 보존하고 history chunk 및 Rules는 변경하지 않는다.
- 원격 dev에는 무관한 PR #6 작업이 있으므로 로컬 dev 변경만 별도 복구 브랜치/PR로 전달한다.

## 변경
- 저장 준비 검사의 지연 환율 예외를 공급자 근거·부분 인증 일치로 제한하고, 저장 정규화·가져오기·재조회에서 근거를 보존한다.
- 성공 알림과 기록 목록에 비차단 잠정 표시를 추가한다. 모바일에서 숨기는 메모 열 대신 총자산 열에 환율일과 근거 펼치기를 제공한다.
- 확정 성과 평가점 생성 제한을 유지하고 AI 내보내기에서도 DELAYED_CLOSE/STALE을 보존한다.
- 스키마 승격·미지원 미래 버전 회귀 기대값과 16MB 백업 fixture 크기(+1바이트)를 갱신한다.

## 검증
- 저장 JSDOM 회귀: 지연 종가 저장·연속 클릭 1회·실제일/출처/조회시각 보존·긴 지연 허용·현재 평가 회복/과거 불변·비정상 환율 거부.
- Chromium + 실제 Firestore Emulator: 버튼 클릭 → IndexedDB → 소유자 Rules 검사 → history chunk 및 활성 포인터 쓰기 → 앱 재조회 → 캐시가 없는 별도 browser context 재조회 통과.
- 비소유자·비로그인의 primary/chunk 쓰기 및 chunk 읽기 거부, 기존 기록/원장 불변 확인. 1440/1280/390/430px에서 잠정 상태·실제일·근거 펼치기·문서 가로 넘침 없음 확인.
- 실제 저장 경로는 repo의 firebase npm SDK로 Emulator에 연결했다. 운영 Google 로그인·운영 Firestore 쓰기는 수행하지 않았다. 외부 자원은 차단했고 인증서 경고는 우회하지 않았다.
- 전체 `npm test`는 Python 3.12 임시 venv·Node 24.19·Java 21 환경에서 Firestore Rules 포함 종료 코드 0으로 통과했다. PR CI/운영 배포는 최종 확인 중. 테스트 로그·스크린샷·개인 자료는 Git에 포함하지 않는다.
