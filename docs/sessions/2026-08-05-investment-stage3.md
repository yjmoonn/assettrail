# 투자 기능 3단계 — 거래·현금흐름 원장

## 목적

자산 수량 변화와 외부 현금흐름을 분리해 기록하고, 매수·매도와 CASH 변화를 하나의
검증 가능한 작업으로 연결해 향후 TWR·XIRR과 성과 원인 분석의 기반을 만든다.

## 핵심 결정

- 기존 보유분의 과거 매수 이력을 추정하지 않고 v5 원장 기준일의 명시적
  `OPENING_BALANCE`로 이전한다.
- 원장 이벤트는 append-only로 유지한다. 정정은 `correctsEventId`, 취소는
  `targetEventId`와 감사일·사유를 가진 새 이벤트로 남긴다.
- US 거래의 native 가격·통화와 당시 환율은 보존하되, 현재 CASH 자산은 원화 단일
  잔액이므로 결제금·수수료·세금은 원화로 정산한다.
- 이벤트는 주 문서에 넣지 않고 활성 ledger 세대의 하위 컬렉션에 저장한다. 대량
  교체는 새 세대에서 검증한 뒤 manifest를 원자적으로 전환한다.
- 기존 `realizedTrades`는 기준일 이전 참고 기록으로 보존하고 SELL 이벤트로 소급
  재생하지 않는다. 기존 US 기초잔액의 알 수 없는 과거 환율도 추정하지 않는다.

## 변경

- `ledger-engine.js`에 BUY·SELL·입출금·배당·이자·수수료·세금·SPLIT·VALUATION·FX,
  기초잔액·취소 검증과 포지션·CASH 투영을 추가했다.
- 매수·매도 폼에 결제 CASH 선택을 연결하고, 거래 원장 탭에 현금흐름 6종,
  정합성 요약, 정정·취소 감사를 추가했다. MANUAL 금액 수정은 평가조정 이벤트다.
- 기초잔액만 있는 MARKET 자산의 티커는 기초잔액 정정 이벤트로 바꾸고, 오등록
  자산은 기초잔액 취소 이력을 남긴 뒤 목록에서 정리할 수 있게 했다. 후속 거래가
  있는 자산의 식별자 변경·삭제는 거래가 나중에 취소돼도 계속 차단한다.
- 신규 자산의 동일 identity 덮어쓰기를 없애고, 가져오기 파일의 자산 identity와
  주요 컬렉션 ID 중복을 상태 반영 전에 거부한다.
- 저장 스키마를 v5로 올리고 로컬 검증 백업, 기초잔액 이전, 이벤트·원장 메타의
  내보내기·가져오기 및 양방향 참조·잔액 검증을 추가했다.
- 클라우드 이벤트를
  `users/{uid}/financeData/primary/ledgers/{ledgerId}/events/{eventId}`에 분리했다.
  고정 fingerprint와 주 문서→events→주 문서 최대 3회 읽기, 400건 이하 transaction,
  400건 초과 새 세대 staging·원자적 manifest 교체를 적용했다.
- 스키마 이전과 강제 충돌 업로드 전에 변경 불가능한
  `users/{uid}/financeData/primary/backups/{backupId}` 사본을 생성하고 Firestore
  Rules에서 다른 사용자 접근과 원장 이벤트·백업 삭제를 차단했다.

## 검증

- `npm test`: 전체 통과. 원장 엔진·앱 통합, v1~v4→v5 이전·백업·복구,
  가져오기 참조·잔액, 클라우드 세대·revision·fingerprint 충돌과 Firestore Rules를
  포함한다.
- Chrome 실화면: 1440px, 1280px, 실제 CDP 390px·430px 통과. 거래 원장,
  매수·매도와 현금흐름 폼에서 가로 오버플로와 브라우저 오류가 없고 모바일 주요
  컨트롤은 44px 이상이다.
- `git diff --check`: 통과.
- 커밋·푸시·운영 배포는 실행하지 않았다.
