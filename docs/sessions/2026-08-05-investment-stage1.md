# 투자 기능 1단계 — 의사결정 체계 구축

## 목적

보유 이유와 다음 검토 행동을 구조화하고, 현재 보유 데이터만으로 계좌를 합친
경제적 포지션과 기본 집중 위험을 확인할 수 있게 한다.

## 핵심 결정

- 계좌별 보유 행은 `assetId`, 공유 판단은 시장·정규화 티커 기반 `subjectKey`로
  구분한다. CASH·MANUAL과 티커가 없는 자산은 `assetId` 단위로 유지한다.
- 관심종목은 별도 `watchlist`로 관리하고 총자산·집중도에는 포함하지 않는다. 이미
  보유한 같은 종목의 신규 관심종목 등록은 공유 판단을 실수로 덮지 않도록 막는다.
  미참조 기존 프로필을 다시 연결할 때는 기존값 불러오기와 새 초안 유지 중 선택하고,
  초안을 유지하면 두 기록을 비교한 다음 다시 저장하게 한다.
- 스키마 v3가 추가 컬렉션을 명시하며 v2는 자동 이전한다. 구버전이 v3를 읽으면
  저장을 멈춰 새 데이터를 삭제하지 않게 한다. 동일 티커의 계좌별 v2 판단이 서로
  다르면 모든 원본을 구조화해 보존하고 명시적 저장 전까지 충돌로 표시한다. 자산
  티커 변경 대상에 기존 프로필이 있고 이전 판단의 마지막 참조가 사라지면 그 판단을
  충돌 원본으로 옮겨 보존한다. 다른 계좌가 이전 종목을 계속 보유하면 두 판단은
  분리한다.
- PR #6에서는 결정론적 그룹화·집중도 개념만 현재 모델에 맞춰 재구현하고,
  거래 원장이 필요한 수익률과 외부 데이터·AI 기능은 가져오지 않는다.
- 미래 거래 원장은 별도 `eventId`를 사용하고 원본 거래 ID와 자산 참조를 분리한다.

## 변경

- `decision-engine.js`: 경제적 포지션, Top 1·Top 5·HHI, 유효 포지션 수, 검토 시점과
  데이터 품질 경고를 계산한다.
- `app.js`, `index.html`, `styles.css`: 자산 상세 판단 폼, 대시보드 기한 초과 작업,
  의사결정 센터, 관심종목 CRUD와 반응형 UI를 추가했다.
- 로컬·클라우드·가져오기·내보내기·충돌 fingerprint를 스키마 v3에 맞췄다.
- Pages 배포가 새 엔진 파일과 전용 테스트를 포함하도록 워크플로를 갱신했다.
- README, 아키텍처, 테스트와 활성 TODO 문서를 실제 동작에 맞췄다.
