# 예수금 준비 없이 매매 기록

## 목적
예수금 항목을 먼저 만들거나 잔액을 채우지 않아도 거래를 기록하고 매도대금은 자동 집계한다.

## 핵심 결정
- 같은 계좌 CASH 자동 연결·생성. 여러 후보만 명시적으로 선택하며 다른 계좌에 임의 연결하지 않는다.
- 미확인 기존 잔액과 실제 0원 구분. 미확인 계좌의 음수 금액은 거래 증감으로 보존하고 실제 부채로 평가하지 않는다.
- 실제 입금 선택 없이 DEPOSIT을 생성하지 않는다. 확인된 계좌·포지션·원장 참조의 기존 검증은 유지한다.

## 변경
- app.js: 자동 CASH와 거래를 한 저장 작업으로 반영·롤백. 미확인 잔액의 나중 확인·내보내기·재조회·동기화 지원.
- ledger-engine.js: 지정된 미확인 CASH의 음수 증감 허용과 경고. 검증 성과점은 미확인 잔액이 있으면 제한.
- v11: 확인 상태를 직렬화하고 기존 v10 백업 및 구버전 쓰기 보호를 적용.
- UI의 CASH 필수 선택 제거, 0원 CASH 직접 등록 허용, 총자산 일부 미확인·현금 거래 증감·조회 품질 표시.
- 신규 회귀: CASH 없는 첫 매수·매도, 수수료·세금 차감, 같은 계좌 재사용, 부족 잔액 매수, 가짜 입금 방지, 취소·실제 잔액 확인·재조회·가져오기.

## 검증
- 원장, 데이터 보존, 클라우드 동기화·충돌, 가격 및 실제 Firestore Emulator 권한 검사를 실행.
- 로컬 Chrome 실행은 ProcessSingleton socket 권한 제한으로 시작 실패. 예외 플래그로 우회하지 않았다.
- PR CI에 Chromium 1440/1280/430/390px의 매도·부족 잔액 매수·재조회·가로 넘침 검증과 합성 데이터 스크린샷을 추가.
- Java 21과 프로젝트 격리 Python 의존성 환경에서 최종 `npm test` 전체 종료 코드 0. 원장·성과·CSV·가격·히스토리·클라우드·데이터 보존·가격 생성기·실제 Firestore Rules 검사 통과.
- 브라우저 검증은 로컬 실행 환경 제한으로 미실행이며, CI 실행·운영 배포도 아직 수행하지 못했다.
