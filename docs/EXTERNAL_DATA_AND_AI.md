# 외부 데이터, ETF 실질노출과 AI 가이드

기준일: 2026-08-19

현재 핵심 제품에서는 Butler·ETF·기존 AI 분석 작업공간을 일몰했다. 과거에 사용자가
저장한 기업 스냅샷과 ETF 카탈로그는 삭제하지 않고 사용자별 로컬 저장소와 설정의
`기존 확장 데이터 백업`에서 보존한다. 아래 Butler·ETF 계약은 신규 사용 흐름이 아니라
레거시 데이터 검증·백업 호환을 위한 설명이다.

현재 제공하는 AI 기능은 설정의 `ASSETTRAIL_AI_REVIEW_V1` Markdown 내보내기다. 앱은
공급자 API, 모델 API, ChatGPT 계정, 결과 가져오기·저장과 자동 주문을 연결하지 않는다.

## 현재 제공 범위

| 기능 | 현재 방식 | 영구 저장 | 자동 네트워크 호출 |
|---|---|---|---|
| AI 월간 점검 | 고정 프롬프트와 최소 상대지표를 Markdown으로 다운로드 | 저장하지 않음 | 없음 |
| Butler 기업 실적 | UI 일몰. 기존 정규화 사실의 별도 백업·복원만 유지 | 사용자별 레거시 로컬 저장 | 없음 |
| ETF 구성종목 | UI 일몰. 기존 검증 카탈로그의 별도 백업·복원만 유지 | 사용자별 레거시 로컬 저장 | 없음 |
| 기존 AI 보고서 | UI 일몰. 엔진·테스트는 저장 호환 회귀용으로 유지 | 저장하지 않음 | 없음 |

기업 스냅샷과 ETF 카탈로그는 v7 주 자산 데이터, Firestore, 클라우드 동기화와 JSON
내보내기에 포함되지 않는다. 로그인 사용자가 바뀌면 별도 로컬 저장 키도 전환되지만,
브라우저 저장소 자체는 암호화 금고가 아니다. 공용 기기에서는 사용 후 브라우저
사이트 데이터를 지워야 한다. 설정의 `기존 확장 데이터 백업`으로 별도
파일을 만들 수 있고, 저장소가 손상되거나 한도를 넘으면 원본을 덮어쓰지 않은 채 백업과
해당 저장소만 비우는 복구 흐름을 안내한다. 사용자 전환 때 입력·상태·AI 결과 DOM도
즉시 지우고, 읽는 중이던 외부 데이터·ETF 파일 가져오기도 취소해 이전 사용자의 파일이
새 사용자 저장소에 기록되지 않게 한다. 저장 직전에는 마지막으로 읽은 로컬 원문과 현재
원문을 비교하며, 다른 탭에서 바뀌었으면 쓰기·비우기를 중단한다. 다른 탭의 변경은
브라우저 `storage` 이벤트로 다시 읽는다. 파일을 읽는 동안 같은 저장소를 비우면 대기
중이던 가져오기도 취소해 삭제한 데이터가 뒤늦게 되살아나지 않게 한다.

외부 데이터 백업은 `백업 가져오기`로 전체 검증 후 복원할 수 있다. 기존 외부 저장소나
ETF 카탈로그를 파일로 교체하기 전에는 현재 원본을 먼저 내려받으며, 기업 스냅샷을
개별 삭제할 때도 삭제 전 외부 데이터 백업이 성공해야 한다. ETF 백업은 같은 카탈로그
업로드 경로로 검증·교체한다.

## 레거시 Butler 수동 가져오기

아래 입력 화면은 현재 내비게이션에서 접근할 수 없다. 이미 저장된 정규화 데이터의
형식과 백업 검증을 설명하기 위해 남긴다.

1. Butler 공식 화면에서 대상 기업과 재무정보 기간을 확인한다.
2. `재무정보 테이블 복사하기`로 표를 복사한다.
3. 당시 제공되던 AssetTrail 분석 화면에서 기존 자산, 통화와 Butler 공식 출처 URL을 확인한다.
4. 표를 붙여넣고 미리보기를 실행한다.
5. 기간, 확정치·컨센서스, 인식·제외 항목과 진단을 확인한 뒤 저장한다.

앱은 연도, 분기와 4분기누적(TTM)을 구분한다. 매출액, 영업이익, 순이익, 자산·부채·
자본, 영업현금흐름, CAPEX, FCF처럼 허용된 사실만 정규화한다. 단위가 명시된 값은
그 단위를 적용하지만, 표에 없는 통화나 암묵적 배율은 추정하지 않으므로 사용자가
시장·통화를 확인해야 한다. 예상 기간·값은 `CONSENSUS`, 확정 값은 `ACTUAL`로 분리한다.
`ACTUAL`의 기간 종료일이 출처의 UTC 조회일(`retrievedAt`)보다 미래이면 저장된 백업을
다시 검증할 때도 거부한다. 미래 기간의 `CONSENSUS`는 예상치이므로 허용한다.

저장되는 출처 계약은 아래와 같다.

```text
provider: BUTLER
acquisitionMethod: BUTLER_MANUAL
authority: SECONDARY_AGGREGATOR
suppliedBy: USER_SUPPLIED
```

붙여넣은 원문은 미리보기 동안 브라우저 메모리에만 있고 저장 후 입력란에서 제거한다.
원문, 알 수 없는 행, 인증 토큰과 URL 쿼리는 스냅샷·오류·로그에 넣지 않는다. 앱은
Butler 로그인 자동화, 세션 쿠키 재사용, HTML 스크래핑과 비공개 내부 API 호출을 하지
않는다. Butler 데이터는 보조 집계 출처이므로 원문 공시와 다를 수 있고, 앱이 이용권한이나
정확성을 대신 보증하지 않는다.

Butler 출처는 HTTPS `butler.works` 주소만 허용한다. URL의 사용자명·비밀번호, 비표준
포트와 유사 도메인은 거부하고 query와 fragment는 저장 전에 모두 제거한다. 정규화
스냅샷은 유효한 ISO 조회 시각 `retrievedAt`이 필수이고 현재 시각보다 5분을 초과해
미래이면 거부한다. 최대 60개이며, 한도를 넘는 경우 조용히 잘라 저장하지 않는다.

## 레거시 ETF 카탈로그와 실질노출

카탈로그는 `assettrail.etf-holdings.v1` JSON이다. 아래는 형식 설명용 최소 예시다.

```json
{
  "schemaVersion": "assettrail.etf-holdings.v1",
  "generatedAt": "2026-08-07T00:00:00Z",
  "asOf": "2026-08-06",
  "source": {
    "name": "사용자가 확인한 운용사 자료",
    "url": "https://example.com/official-holdings",
    "retrievedAt": "2026-08-07T00:00:00Z"
  },
  "redistribution": "USER_SUPPLIED",
  "funds": [
    {
      "instrumentId": "KRX:069500",
      "name": "예시 ETF",
      "structure": "PHYSICAL_LONG_ONLY",
      "asOf": "2026-08-06",
      "holdings": [
        { "instrumentId": "KRX:005930", "weight": 0.6 },
        { "instrumentId": "KRX:000660", "weight": 0.3 },
        { "bucket": "CASH", "weight": 0.1 }
      ]
    }
  ]
}
```

비중은 0~1 사이이며 펀드별 합계는 1이어야 한다. 일부가 공개되지 않았다면 엔진이
누락분을 `UNREPORTED`로 명시한다. 표준 종목 ID는 `KRX:005930` 또는 `US:AAPL`
형식이다. 출처 URL, 기준일, 생성/조회 시각과 재배포 상태를 확인할 수 없는 카탈로그는
운영 데이터처럼 사용하지 않는다. 카탈로그와 각 펀드가 상속하거나 선언하는 출처에는
유효한 ISO 조회 시각 `retrievedAt`이 반드시 있어야 하며 현재 시각보다 5분을 초과해
미래인 조회 시각은 거부한다.

출처와 재배포 조건 URL은 HTTPS만 허용하며 사용자정보, query와 fragment가 있는 URL은
거부한다. 최대 펀드 500개, 펀드당 구성 2,000개, 전체 구성 25,000개, 포트폴리오 위치
10,000개를 넘는 입력도 거부한다. 같은 펀드 안의 중복 종목 ID는 합치지 않고 수정하도록
요청한다.

계산은 실물·롱온리 펀드만 지원한다. 합성, 레버리지, 인버스, 숏과 구조가 불명확한
펀드는 실패 상태로 둔다. 직접 보유한 종목과 ETF 속 같은 종목은 하나로 합치지만 ETF
포장 자체를 다시 더하지 않는다. 중첩 ETF는 최대 깊이와 순환 참조를 제한하고,
`CASH`, `OTHER`, `UNMAPPED`, `UNREPORTED`, `UNSUPPORTED`를 별도 버킷으로
보존한다. 종목 노출과 이 버킷들의 합이 원래 포트폴리오 평가액과 맞지 않으면 결과를
신뢰 가능한 자동 투시로 표시하지 않는다.

직접 포지션은 종류가 `ETF`·`FUND`·`ETN`으로 명시된 경우에만 카탈로그 펀드로
확장한다. 주식 또는 종류가 없는 직접 포지션 ID가 카탈로그 ID와 겹치면 원래 직접
종목으로 보존하고 결과를 `LIMITED`로 낮춘다. 구성종목의 `instrumentKind`가
`ETF`·`FUND`·`ETN`이면 해당 하위 펀드 카탈로그가 없을 때 종목으로 추정하지 않고
전액을 `UNSUPPORTED`로 보존한다. `STOCK`으로 명시된 구성종목은 같은 ID의 펀드
행이 있어도 주식으로 유지한다. 종류 필드가 없던 v1 카탈로그는 하위 ID의 펀드 행이
실제로 있을 때만 기존 중첩 동작을 유지한다.

중첩 확장은 최대 25,000단계에서 멈추고 남은 금액을 `UNSUPPORTED`로 보존해 브라우저
중단과 금액 유실을 막는다. 카탈로그에 없는 ETF도 직접 금액 전체를 `UNSUPPORTED`로
포함하므로 미매핑 비중이 0으로 축소되지 않는다. 보유 ETF에 실제로 연결된 모든 펀드의
가장 오래된 기준일을 사용하며 14일을 넘으면 `STALE`로 표시한다.

현재 저장소에는 상용 또는 정기 갱신되는 운영 카탈로그를 번들하지 않는다. 사용자는
데이터의 다운로드·분석·저장·재배포 권한을 직접 확인해야 한다. `USER_SUPPLIED`는
사용자가 제공했다는 뜻일 뿐 제3자 재배포 권리를 부여하는 표시는 아니다.

## AI 월간 점검 Markdown

설정의 `AI 점검 패키지 내보내기`는 다음 두 요소를 하나의 `.md` 파일로 만든다.

- `ASSETTRAIL_AI_REVIEW_V1`: 자산군·포지션 비중, 집중도, 검증 성과율, 은퇴 목표
  비율과 점검 상태
- `ASSETTRAIL_MONTHLY_REVIEW_PROMPT_V1`: 데이터 품질을 먼저 확인하고 사실·해석·
  불확실성을 분리하며 사용자가 확정하지 않은 목표 비중을 추정하지 않도록 고정한 분석 지침

현재 앱은 숨겨진 레거시 `portfolioTargets`를 사용자 확정값으로 사용하지 않는다.
`targetComparison.status`는 항상 `DEFAULT_NOT_CONFIRMED`이고 각 자산군의 목표 비중과
차이는 `null`이다. 엔진의 `USER_CONFIGURED` 상태는 향후 명시적인 확인 UI가 생길 때만
사용할 수 있는 계약이다.

UID·이메일·이름, 계좌명, 내부 자산·거래 ID, 원거래, 절대 평가액·거래금액·수량,
자유 메모와 URL은 포함하지 않는다. digest는 `generatedAt`을 제외한 안정 콘텐츠의
canonical JSON SHA-256이며, 패키지는 exact-key 검증을 통과해야 내려받을 수 있다.
사용자는 파일을 원하는 AI 서비스에 직접 첨부한다.

AssetTrail은 OpenAI API 키나 다른 모델 공급자 키를 요구하지 않고, AI 계정에
로그인하거나 파일을 자동 전송하지 않는다. 외부 AI의 응답을 앱으로 다시 가져와 검증·
저장·실행하는 경로도 없다. ChatGPT Pro는 커스텀 웹앱의 모델 API 인증이 아니며 모델
사용량을 자동 소비하지 않는다.

기존 `ASSETTRAIL_AI_EVIDENCE_V1`, `ASSETTRAIL_AI_REPORT_V1`과
`ASSETTRAIL_CHATGPT_HANDOFF_V1` 엔진은 과거 데이터·테스트 호환을 위해 남지만 현재
분석 UI에서는 노출하지 않는다.

## US 가격 대상 운영

미국 가격 대상은 브라우저 보유정보로 자동 확장하지 않고 저장소 `tickers.json`의
검토 이력으로만 관리한다.

```sh
node scripts/manage_us_tickers.mjs review --ticker MSFT
node scripts/manage_us_tickers.mjs add --ticker MSFT --reason "가격 대상 추가 사유"
node scripts/manage_us_tickers.mjs add --ticker MSFT --reason "가격 대상 추가 사유" --apply
```

`add`도 `--apply`가 없으면 파일을 바꾸지 않는다. 적용할 때는 중복과 티커 형식을
검증하고 정렬된 목록을 원자적으로 쓴다. 이 도구는 네트워크 조회나 사용자의 브라우저
포트폴리오를 사용하지 않는다. 변경 후 가격 생성 테스트와 코드 리뷰를 거쳐야 한다.

## 후속 구현 전 승인 항목

- OpenDART와 SEC Company Facts 운영 수집기의 약관, 식별자 매핑과 데이터 정확성
- 백엔드 캐시, 공급자별 속도 제한, 마지막 정상 데이터와 오래됨·장애 상태
- 공식 Butler 개발자 API, 자동 이용과 저장·재배포 권한 또는 별도 라이선스
- 정기 갱신 ETF 공급자의 사용·저장·재배포 권리와 실패 시 대체 정책
- 컨센서스 공급자, 예상 비용과 화면상 확정치 분리 정책
- 자동 AI callable의 Firebase Auth, App Check, 서버측 최신 revision 재검증,
  Secret Manager, 사용량 제한, 모델 공급자와 비용 승인
- 클라우드 분석 저장을 추가할 경우 다른 사용자의 데이터에 접근할 수 없는 Rules 및 E2E

이 항목들이 승인되기 전에는 현재 수동·로컬 경계를 자동 수집이나 유료 API로 조용히
바꾸지 않는다.

## 검증

일반 테스트는 외부 사이트나 모델을 호출하지 않는다.

```sh
npm run test:ai-review
npm run test:product
```

레거시 외부 데이터·ETF·AI 계약을 바꾼 경우에만 아래 회귀도 실행한다.

```sh
npm run test:external-data
npm run test:etf
npm run test:ai
npm run test:stage5
```
